# 作品集网站重构 · 第一阶段开发文档

## 一、项目目标

将现有图片式作品集重构为代码驱动的现代化网站，实现可视化编辑、模块化管理、GitHub 存储及 CDN 加速。

第一阶段仅实现**一个首页及对应的中文管理后台**，不开发多页面管理功能。

## 二、技术架构

- 前端：Astro + React + TypeScript
- 样式：CSS Modules
- 可视化编辑器：Puck（官方版本）
- 界面语言：简体中文，使用官方 Dictionary API
- 内容存储：GitHub + JSON
- 管理接口：Cloudflare Workers
- 部署：Cloudflare Pages
- CDN：Cloudflare，预留 EdgeOne 接入能力

优先使用成熟、稳定的官方方案，减少不必要的第三方依赖。

## 三、页面开发

参考提供的作品集首页设计图，使用 HTML、CSS 和组件化方式高度还原。

要求：

1. 文字必须是真实文本，禁止将整张设计稿作为页面背景。
2. 支持加载用户提供的本地字体文件。
3. 网格、线条、背景、排版优先使用 CSS/SVG 实现。
4. 支持桌面与移动端响应式布局。
5. 页面采用静态生成，优先保证加载速度和视觉还原度。
6. 预留交互动效扩展能力。

## 四、模块化规范

所有页面内容基于独立组件构建。

- 每个模块具有唯一 ID、类型、版本及独立配置。
- 模块之间不得直接依赖内部样式和实现。
- 使用 CSS Modules 隔离样式，避免全局污染。
- 模块配置采用统一 JSON Schema。
- 通过模块注册表统一管理组件。
- 新增模块不得修改已有模块的数据结构。
- 已发布模块的破坏性修改必须通过新版本或数据迁移处理。
- 页面 JSON 与组件源码分离，编辑器只能修改配置，不直接修改源码。

首批只实现首页实际需要的模块，不提前开发无关组件。

## 五、可视化管理后台

集成官方 Puck 编辑器，后台路径为 `/admin`。

实现以下基础能力：

1. 简体中文操作界面。
2. 模块添加、删除、排序。
3. 编辑文字、图片、字体、颜色、间距等已开放属性。
4. 实时预览页面效果。
5. 桌面与移动端预览。
6. 保存草稿与发布页面。
7. 页面数据使用结构化 JSON 保存。

模块样式参数应合理限制，避免编辑操作破坏整体布局。

## 六、GitHub 与部署

- GitHub 作为唯一内容仓库。
- 页面配置、组件代码、图片及字体统一版本管理。
- Cloudflare Worker 负责鉴权和 GitHub API 操作。
- 使用 GitHub App 或最小权限凭证，密钥仅保存在服务端环境变量中。
- 草稿与已发布内容隔离，保存草稿不得触发正式网站更新。
- 发布后触发 Cloudflare Pages 自动构建。
- 支持通过 Git 历史记录回退。
- 禁止在前端暴露任何密钥。

开发阶段允许使用本地 JSON 保存，确保未配置 GitHub 凭证时也能运行和预览。

## 七、开发原则

1. 优先模块解耦和长期可维护性。
2. 不引入传统数据库及常驻服务器。
3. 不修改 Puck 官方源码，通过公开 API 扩展功能。
4. 避免过度设计，仅实现第一阶段必要功能。
5. 保持代码目录清晰，方便未来新增页面和组件。
6. 严格区分开发环境与正式环境。
7. 所有核心功能必须实际可运行，禁止使用假数据模拟已完成的保存或发布功能。

## 八、第一阶段验收标准

- 首页可以正常访问，并高度还原参考设计稿。
- 字体、文字、网格等元素均由代码实现。
- `/admin` 可以正常打开中文可视化编辑器。
- 能够修改首页模块并实时预览。
- 页面 JSON 可以保存、重新加载且内容一致。
- 已配置 GitHub 后，可以完成真实发布。
- 新增独立测试模块不会破坏原有模块。
- 网站可以通过 Cloudflare Pages 构建部署。

## 九、执行要求

首先检查现有项目结构及相关资源，制定最小可行的实施方案，再按模块逐步开发。

优先完成首页视觉还原和模块架构，其次实现 Puck 编辑器，最后集成 GitHub 发布流程。

不要一次性开发完整 CMS，也不要为了未来可能使用的功能增加不必要的复杂度。
## 十、当前实现与本地使用

当前 V2 已建立 Astro + React + TypeScript 项目，参考页面为 `cankao/261105_ZBY_ZPJ_V2,0_内页_01.svg`，保留 Photoshop 界面装饰。导航、主视觉和年份栏分别为独立模块；主标题采用真实 SVG 文字，其他文字为 HTML，未使用整页图片。

需要 Node.js 22.23.4 或满足当前依赖要求的版本。

```bash
npm ci
npm run dev
```

- 首页：`http://127.0.0.1:4321/`
- 中文后台：`http://127.0.0.1:4321/admin`
- 构建：`npm run build`
- 自动测试：`npm test`（首次先运行 `PLAYWRIGHT_BROWSERS_PATH=.cache/ms-playwright npx playwright install chromium`）

本地保存草稿会真实写入 `content/draft/home.json`；发布会更新 `content/published/home.json`。静态首页仅使用发布 JSON，保存草稿不会改变发布内容。后台可以编辑本页已有文字、链接、受控字体、颜色和留白，添加、删除与排序模块，并切换桌面／手机视口。该参考页面无内容图片，图片模块及上传不在当前实现范围内。

GitHub 保存与发布接口、正式环境登录及 Pages Worker 打包已经编写；当前未配置正式凭证或部署，线上链路待真实环境验证。开发后台使用本机文件接口，静态 `preview` 服务不提供编辑保存 API。

长期维护入口：

- [项目结构与开发规则](docs/PROJECT-RULES.md)
- [全局设计变量](docs/DESIGN-TOKENS.md)
- [本地与部署说明](docs/DEPLOYMENT.md)

全局字体、颜色、字号及间距在 `src/styles/tokens.css` 管理；页面内容在 JSON 中管理；各模块的内部样式由 CSS Modules 隔离。新增模块与修改契约须遵守项目结构文档。原字体保存在 `fonts/`，网页使用 `public/fonts/` 的 WOFF2。

装饰开关的“隐藏”会同时移除 Photoshop 外壳、工具栏、标尺、外框留白和主标题辅助线。主标题线框直接使用原参考 SVG 提取的 `public/decorations/portfolio-guides.svg`，不再手工重绘；可执行 `python3 scripts/extract-design-assets.py` 重新提取。

Photoshop 外壳已改为直接复用 `v1.0/ZBY-ZPJ/ps-yemian.svg`，原样复制至 V2 的 `public/decorations/ps-yemian.svg`，已核对文件字节一致。视口适配沿用 V1 的几何规则，由轻量脚本调整侧栏高度与底栏位置；V1 保持只读。

Photoshop 外壳显示时，复用原 SVG 的工具悬停与选中交互，并接通 V1 的滚轮、轨道点击、滑块拖拽和页面滚动同步逻辑；手机支持触摸滑块拖动。此时隐藏浏览器原生滚动条，使用 PS 内置右侧滚动条。关闭外壳会清理交互监听并恢复原生滚动条。中央画布直接接收真实 HTML 的点击与编辑操作。
