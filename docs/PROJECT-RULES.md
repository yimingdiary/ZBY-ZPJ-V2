# V2 项目结构与长期维护规范

本规范适用于 `v2.0/`。`v1.0/` 永久作为只读参考。需求范围与验收以 `README.md` 开发文档为准，执行规则以 `AGENT.md` 为准。

## 1. 目录职责

```text
v2.0/
├── src/
│   ├── pages/                 # Astro 路由；只组装页面，不承载业务模块
│   ├── modules/
│   │   ├── Chrome/            # Photoshop 装饰与页面布局容器
│   │   ├── Navigation/        # 顶部导航
│   │   ├── PortfolioHero/     # 标题、网格及说明文字
│   │   ├── Footer/            # 底部年份栏
│   │   ├── registry.tsx       # 唯一模块注册表、编辑字段与默认值
│   │   └── Page.tsx           # 发布页共用渲染入口
│   ├── styles/
│   │   ├── tokens.css         # 全局设计变量，字体声明
│   │   └── global.css         # 基础重置、可访问性及减少动画设置
│   ├── editor/                # 官方 Puck 的中文词典、保存交互与后台外壳
│   └── content/
│       ├── page.schema.json   # 唯一页面数据规范（JSON Schema）
│       ├── validate.ts        # 跨环境校验入口
│       └── compiled-validation.mjs # 自动生成，不手改
├── content/
│   ├── draft/home.json        # 本地草稿／GitHub 草稿分支配置
│   └── published/home.json    # Astro 构建唯一使用的页面内容
├── worker/index.ts            # 线上鉴权与 GitHub 内容接口
├── scripts/                   # 本地内容接口、Schema 编译、Worker 打包及字体处理
├── public/fonts/              # 页面实际使用的 WOFF2，含完整字库
├── public/_routes.json        # Pages 仅让 /api/* 进入 Worker
├── fonts/                     # 原始字体，不直接整目录发布
├── cankao/                    # 原始参考稿，不作为整页图片渲染
├── tests/                     # 内容隔离、校验、安全边界与浏览器检查
└── docs/                      # 规范、设计变量与部署说明
```

## 2. 四层分工

1. 内容层：JSON 保存文字、链接、模块顺序及开放的属性。
2. 设计层：CSS 设计变量管理全局视觉标准。
3. 模块层：独立 React 组件和 CSS Modules 负责呈现。
4. 编辑及发布层：Puck 仅改 JSON；本地接口或 Worker 负责持久化。

发布页静态生成，不向访客加载编辑器；仅运行原版 Photoshop SVG 必需的轻量视口适配脚本。编辑器与发布页使用同一注册表和模块，避免两套渲染逻辑不一致。

## 3. 设计变量使用规则

详见 `DESIGN-TOKENS.md`。使用 `--color-ink` 等具有语义的变量名，不使用“变量1”“变量2”。

- 全站统一变化改 `tokens.css`；局部排版改所属模块的 `.module.css`。
- 内容文字、链接和受控的样式选项放 JSON，不把 CSS 代码写进 JSON。
- 后台字体选择使用 `display/body` 等受控键，禁止任意字体路径或 CSS 注入。
- 新模块引用公共变量；禁止读取其他模块的内部 class 或 DOM。
- 只有页面级基础规则可进入全局样式；禁止使用全局 `h1`、`nav` 等选择器修改业务模块。
- 模块内部可设置私有 CSS 变量，以模块语义命名；不能借此覆盖其他模块。

## 4. 模块契约与扩展流程

每条内容包含 `type`、`props.id`、`props.version` 和其余独立属性。Puck 创建模块时生成唯一 ID；服务端拒绝重复 ID。

新增模块依次：

1. 新建 `src/modules/模块名/`，包含类型、组件及 CSS Modules。
2. 在 `registry.tsx` 注册类型、中文名称、编辑字段和默认值。
3. 在 `page.schema.json` 增加该类型的分支，不更改其他模块已有契约。
4. 执行 `npm run schema:build`，重新生成可在浏览器与 Worker 使用的校验器。
5. 在隔离测试配置中加入新模块，确认原有模块渲染不变，保存和重载一致。
6. 执行构建和相关测试后再用于真实内容。

破坏性修改增加版本，并提供显式迁移；不得偷偷把旧 JSON 按新结构解释。删除仍被已发布内容使用的模块前，先迁移内容并验证。

JSON Schema 是运行时数据约束的唯一来源；TypeScript 类型与 Puck 字段需要同步维护。生成校验器禁止手工编辑。Puck 的保留字段 `zones` 可为空对象；本阶段不开放嵌套布局，禁止任意 zone 数据。当前有首页实际使用的七种内容模块（导航、封面主视觉、年份栏、个人介绍、目录、贴片作品、结束页），装饰属于根配置；不提前加入无关组件。

## 5. 保存与发布

| 环境／动作   | 写入位置                        | 对发布页的影响                   |
| ------------ | ------------------------------- | -------------------------------- |
| 本地保存草稿 | `content/draft/home.json`       | 无                               |
| 本地发布     | `content/published/home.json`   | 开发首页更新；静态构建需重新执行 |
| 线上保存草稿 | `content-draft` 分支的草稿 JSON | 不改变生产分支                   |
| 线上发布     | `main` 分支的发布 JSON          | 由 Pages Git 集成触发构建        |

所有写入先验证 JSON Schema。前端不得保存源码、任意文件路径或任意分支；凭证只在 Worker。提交成功不等于部署成功，界面必须准确说明等待构建。

本地 API 仅供回环地址开发使用，不得暴露到公网；正式环境不提供本地文件写入接口。GitHub 拒绝写入或分支冲突时必须报告失败，不显示成功，不绕过权限。

## 6. 资源与响应式

- 原字体保存在 `fonts/`；发布字体保存在 `public/fonts/`。`scripts/prepare-fonts.py` 转换为 WOFF2，保留完整字库以支持后台编辑新文字。额外生成当前页面的小字库，首屏优先加载小字库，新增字符再按需加载同源的完整字库。
- 新增图片使用有意义的文件名，集中在 `public/images/`；第二屏照片存于 `public/images/`，配置仅允许站内 `/images/` 路径；不预建图片上传系统。
- 参考稿是 1920×1080。桌面保留排版比例，手机重新组织导航与说明，不能用整体缩小截图代替响应式。
- Photoshop 工具栏是视觉装饰，不冒充真正可操作的图像编辑器工具。
- 分类页面未在第一阶段范围内；未提供真实目标的分类显示为文字，不能伪造可访问的作品链接。

## 7. 验证与文档

- 构建必须通过 TypeScript 检查和静态生成。
- 保存／发布涉及真实文件修改，测试必须在结束时恢复原内容，测试进程串行执行。
- 至少检查桌面与手机布局、字体加载、页面横向溢出、浏览器异常、草稿隔离和非法配置拒绝。
- Cloudflare 与 GitHub 的真实上线验收必须用正式凭证验证；接口单元测试不等于已上线。
- `CONTEXT.md` 记录当前事实与决策；`README.md` 记录使用方法；本规范记录长期规则。
- `PROGRESS.md` 严格遵循 AGENT 的拉取／推送限制，普通开发不更新。

## 8. 装饰素材与隐藏行为

- 标题线框原素材位于 `public/decorations/portfolio-guides.svg`；提取脚本保留源 SVG 的 12 条线、20 个圆点及其原始坐标和样式。禁止用近似手绘替换。
- `src/design/DecorationVisibility.tsx` 是页面装饰显隐的公共上下文，模块不得通过彼此内部 DOM 控制显隐。
- 隐藏时所有装饰及其布局占位一并消失，正文画布从视口边缘开始。
- V1 装饰只能在找到具体源文件后复制到 V2 复用，禁止在 V1 中构建或修改。

Photoshop 外壳直接复用 `v1.0/ZBY-ZPJ/ps-yemian.svg` 的原样副本，存于 V2 的 `public/decorations/ps-yemian.svg`。`src/design/photoshop-frame.ts` 沿用 V1 的 viewBox、侧栏及底栏适配规则；公开页与 Puck 预览共享此函数，不再维护近似手绘工具图标。

- 工具悬停、选中由原 SVG 内置脚本负责；滚轮、轨道点击、鼠标及触摸滑块拖拽、滚动位置同步统一由 `photoshop-frame.ts` 管理。
- 外壳显示时仅在所属文档设置 `data-ps-scrollbar="custom"` 并隐藏原生滚动条；隐藏或卸载时必须恢复先前状态，移除本次监听、观察器与样式，不能影响后台外层页面。
- 外壳仅在边框区域接收指针，中央画布通过裁切留空直接响应真实 DOM。V1 图片热区的转发机制不套用到 V2 的真实文字、链接及编辑器上。
- 滑块触摸必须主动阻止原生手势取消拖拽；中央正文仍保留浏览器正常触摸滚动。
- 修改交互后验证长页面的滚轮、轨道、滑块及位置同步，验证工具悬停/选中、正文点击和反复显隐后的原生滚动条恢复。

## 9. 目录与结束页

- `Contents` 和 `Closing` 各自维护独立属性及 Schema 分支；结束页通过 Navigation 和 Footer 的公开 Props 组合呈现，不读取其内部样式。
- `src/design/FramedTitle.tsx` 与 `title-frame.ts` 供个人介绍和目录共用，编辑器 React 与发布页脚本调用同一字形测量函数。
- 目录分类有实际链接才渲染为链接；未配置保持文字，不建立虚假作品目标。
- `scripts/extract-section-assets.py` 只读第 03、20 张原稿，生成分类辅助框、结束页辅助线、花形和字母排版参数，不输出整页图片。

## 10. 贴片交互与素材

- `OverlayGallery.items[].workId` 为可选受控枚举，可为空；已有未关联项继续显示普通图片，保留版本 1 配置兼容性。
- 首页和编辑预览共用 `OverlayGallery/preview.ts` 的悬停生命周期；静态首页由轻量脚本初始化，编辑器组件卸载时清理监听。
- 分层详情路由只构建固定作品 ID，独立文档加载从 V1 提取并适配的 `public/overlay/detail.js` 与 `detail.css`，不污染首页样式。
- `public/images/works/catalog.json` 保存来自真实导出 JSON 的图层坐标与素材路径，`scripts/import-overlay-layers.py` 只读素材源、仅写 V2。不能将静态导出文件名里的“动”视作真实动画。

## 11. 素材选择与机器路径

- 作品素材统一放在 `public/images/works/{id}`，catalog 是封面和动画关系的唯一数据源；配置只保存图片站内路径和 `dynamic`，兼容读取原有可选 `workId`。
- `src/assets/works.ts` 负责封面识别、旧路径别名与 public/dist 路径转换；不可将用户粘贴的绝对路径用于任意磁盘读取。
- `scripts/image-library.mjs` 扫描公开封面和普通图片，排除动画与分层内部文件；构建输出 `public/image-library.json`，本地开发按请求读取最新图片库。
- `scripts/local-assets.mjs` 提供本机同源二进制图片导入，按文件内容识别已有文件或写入 `public/images/uploads`；不按用户文件名拼接写入路径，不接受符号链接目录逃逸。
- 编辑器使用 Puck 公开 CustomField API，作品项使用原生 array 字段，只在路径处通过 `ImagePicker` 更新配置；不改 Puck 源码。动态选择受图片对应作品的动画能力约束，服务端 Schema 同步校验。

## 12. 原生装修结构与原名规则

- 新字段沿用 Puck 原生列表、折叠、拖动排序和删除交互；禁止为图片项再维护一套自定义列表 UI。作品项仅开放路径、名称、是否动态，作品使用纵向的文件夹选择按钮和只读实际路径，个人照片继续使用单图选择器；所有控件以 border-box 和 min-width:0 约束在原生字段容器内。
- 作品物理目录使用完整源项目名，图层文件保留源文件名，封面使用“贴片预览.jpg”；记录 sourceName、folderName 与稳定内部 ID，避免把展示名称、物理路径和历史 URL 混作同一标识。
- `scripts/work-directories.py` 负责导入器的命名和目录归属冲突检查；同名不同作品追加稳定后缀，不能覆盖已有目录或默默改为英文别名。
- 新上传图片保留原文件名，按内容哈希放入独立目录；写入使用排他创建，已有内容不同则拒绝覆盖。旧英文目录路径仅保留在别名中，活动配置及磁盘目录使用源名称。
- 图片路径 Schema 允许中文、空格与原名中的 &，拒绝路径穿越、控制符和编码穿越。选择器转换浏览器编码路径后再保存站内地址。

## 13. 文件夹选择与导入

- `WorkFolderPicker` 只负责浏览器目录选择、状态和只读路径展示，不直接写源码或构造图层；字段顺序固定为名称、文件夹、实际路径、是否动态。
- `scripts/work-folders.mjs` 校验目录相对结构，识别已登记作品、规范 `作品.json`、Photoshop `*_layout.json` 或单图目录；禁止以猜测坐标补齐多图作品。
- 新目录在 V2 的 .cache 暂存并校验，确认后迁入作品根目录；索引和 Schema 同步更新，失败回滚，不覆盖已有同名作品。目录导入接口限制为本机同源。
- `作品.json` 是由 catalog 生成的可携带作品说明，所有素材引用均相对当前作品目录；catalog 仍是项目统一素材索引。构建和本地导入会同步生成说明文件。
- 编辑器首次进入才读取草稿；素材索引引起 Fast Refresh 时保留当前数据，不能重新加载旧草稿覆盖尚未保存的输入。
